## Auth model

- **JWT access token** (short-lived, ~15 min) — issued on login
- **JWT refresh token** (long-lived, ~30d) — used to mint new access tokens
- **httpOnly cookies** — access + refresh tokens
- **bcrypt** — password hashing (12 rounds)
- **RBAC via `roles` + `user_roles` + `role.permissions` JSON** — permission
  strings like `statics-generation:access`, `ads:launch`, etc.
- **Middleware** — `authenticate` extracts + verifies JWT, `requirePermission`
  checks user has the specific permission

## Cron gating

Public cron trigger endpoints are gated by `CRON_SECRET`:
- `?secret=$CRON_SECRET` (query param)
- `x-cron-secret: $CRON_SECRET` (header)

Both variants exist across the codebase. Keep them synced when rotating.

## Postgres schema highlights

- **product_profiles** — the source of truth for brand-scoped tables
- **spy_creatives** — every AI-generated creative (up to millions rows)
- **statics_launches** — Meta ad launch log
- **image_store** — BYTEA image blobs (only when R2 not configured)
- **brand_spy schema** — competitor ad library (brand_spy.brands, .ads, etc.)
- **users, roles, sessions, audit_logs** — platform auth
- **_migrations** — migration tracking (managed by `npm run migrate`)

Migration files live in `server/migrations/*.sql`, run via
`node server/migrations/run.js`. Ordered by filename prefix (`001_`, `002_`,
etc.).
